## Requirements

| Requirement | Minimum | Recommended |
|---|---|---|
| CPU | 4 cores | 8+ cores |
| RAM | 16 GB | 32 GB |
| GPU | — | NVIDIA (for Christopher-AI) |
| OS | Ubuntu 20.04+ | Ubuntu 22.04 |
| Docker | 20.10+ | Latest |
| docker-compose | v1 or v2 | v2 |

FusionAL's reference deployment runs on a Dell T3610 workstation with a GTX 1050 Ti. The MCP stack requires no GPU. Christopher-AI (llama.cpp) benefits significantly from CUDA offloading.

## Stack overview

```
fusional-stack/
├── compose.yaml          # Main docker-compose file
├── gateway/              # FusionAL MCP gateway (port 8009)
├── bi-mcp/               # Business Intelligence MCP (port 8101)
├── api-hub/              # API Integration Hub (port 8102)
├── content-mcp/          # Content Automation MCP (port 8103)
├── intel-mcp/            # Intelligence MCP (port 8104)
├── github-mcp/           # GitHub MCP Safe (port 8105)
└── management-api/       # Service start/stop API (port 8099)
```

Christopher-AI runs as a separate process (llama.cpp server) on port 8090.

## Step 1 — Clone the repos

```bash
git clone https://github.com/jrm-fusional/mcp-consulting-kit
cd mcp-consulting-kit
```

## Step 2 — Configure environment variables

Copy the example env file and fill in your values:

```bash
cp .env.example .env
```

Key variables:

```bash
GITHUB_PAT=          # GitHub Personal Access Token for github-mcp
ANTHROPIC_API_KEY=   # Used by intelligence-mcp for cloud fallback
MGMT_API_TOKEN=      # Bearer token for the management API
```

<Warning>
  Never commit `.env` to version control. The management API and GitHub PAT must stay in environment variables, not embedded in config files.
</Warning>

## Step 3 — Start the stack

```bash
docker-compose up -d
```

Check that all containers are healthy:

```bash
docker-compose ps
```

All six services should show `Up (healthy)`.

## Step 4 — Expose via Cloudflare Tunnel (optional)

If you want services accessible over the internet without port-forwarding, use Cloudflare Tunnel.

See [Cloudflare Tunnels](/infrastructure/cloudflare-tunnels) for the full setup guide.

## Verifying health

Each service exposes a `/health` endpoint:

```bash
curl http://localhost:8009/health   # gateway
curl http://localhost:8101/health   # bi-mcp
curl http://localhost:8102/health   # api-hub
curl http://localhost:8103/health   # content-mcp
curl http://localhost:8104/health   # intel-mcp
curl http://localhost:8105/health   # github-mcp
```

A healthy response looks like:

```json
{ "status": "ok", "service": "fusional-gateway", "uptime": 3920 }
```

## Christopher-AI (optional)

Christopher-AI is a separate llama.cpp server. To start it:

```bash
./llama-server \
  -m /path/to/Llama-3.2-3B-Instruct-Q4_K_M.gguf \
  --host 0.0.0.0 \
  --port 8090 \
  -ngl 99
```

The `-ngl 99` flag offloads all layers to GPU. Remove or reduce if you have no GPU.

See [Christopher-AI Configuration](/christopher-ai/configuration) for full options.

## Updating

```bash
git pull origin main
docker-compose pull
docker-compose up -d
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Container starts but health check fails">
    Check container logs: `docker-compose logs <service-name>`. Look for port binding errors or missing env vars.
  </Accordion>
  <Accordion title="Claude Desktop can't reach the gateway">
    Verify you're using the correct IP/domain in `claude_desktop_config.json`. `localhost` only works when Claude Desktop runs on the same machine as the stack. Use Tailscale IP for cross-machine access.
  </Accordion>
  <Accordion title="docker-compose vs docker compose">
    The reference deployment uses docker-compose v1 (`docker-compose`). If you're on a system with only v2, use `docker compose` (no hyphen) instead.
  </Accordion>
  <Accordion title="GPU not detected for Christopher-AI">
    Verify CUDA is available: `nvidia-smi`. Ensure the Docker container has GPU passthrough enabled if running inside Docker. llama.cpp built without CUDA will fall back to CPU automatically.
  </Accordion>
</AccordionGroup>
